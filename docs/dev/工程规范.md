# 工程规范（M0）

本文固化三条 M0 内强制执行的工程规范：S9 状态机/DAG 边界、任务卡四段式制度、目录边界。所有 todos 1-11 与后续开发遵循本文；本文不改 05 门禁标准，仅做执行级细化。

## S9 状态机/DAG 边界

- XState v5 只管**任务生命周期**（任务卡从派发→运行→暂停→失败→完成等宏状态流转），见 04-架构评审报告.md 第 92 行（S9 边界要求）。
- 自研 DAG 执行器只管**步骤拓扑与检查点**：步骤间依赖编排、断点续跑、检查点写入/恢复语义见 02-系统架构设计.md 第 145 行（§3.1 选型行：XState v5 + 自研 DAG）及 02-系统架构设计.md 第 257-262 行（§6.1 检查点语义）。
- **步骤级状态禁止进入 XState**：任何单个 DAG 步骤的中间态（进度、重试计数、检查点游标等）一律归属 DAG 执行器内部状态，不得建模为 XState 子状态机。

## 任务卡四段式制度

每张任务卡的完成报告必须包含四段，缺一不可（依据 05-AI开发计划与里程碑.md §8 机制 3）：

1. **产物**：本次交付的文件/模块/配置清单。
2. **证据**：命令输出、测试结果、截图等可核查凭证（对应 .omo/evidence/ 路径）。
3. **自测**：执行者自己跑过的 happy/failure QA 场景及结果。
4. **风险**：已知遗留问题、降级项、需升级确认的事项。

无证据项一律判未通过：四段中任何一段缺失，或证据段为空/与产物不符，该任务卡视为未完成，不得进入验收。

## 目录边界

Monorepo 目录边界约定（配套机读规则见仓库根 `eslint.boundaries.mjs`）：

- `apps/*` 之间**禁止互相 import**（如 apps/desktop 不得 import apps/server 的任何模块）。
- 跨层（app→package、跨端通信契约）**只允许经 `packages/protocol`** 引用共享类型与契约；app 不得直接 import 其他业务包内部实现。
- **基础设施豁免**：`packages/logger` 属横切基础设施（纯日志管线，无业务语义，M0 门禁会确认），允许 app 直接引用——机读规则同步放行（F2/Q4 规则层化，替代逐处 eslint-disable）。
- 包名→职责表：

| 包名 | 职责 |
| --- | --- |
| packages/protocol | 共享契约与类型（跨端 IPC/API 契约，唯一跨层通道） |
| packages/workflow | 任务生命周期状态机 + DAG 执行器（含检查点） |
| packages/logger | 统一日志采集与脱敏 |
| packages/llm-gateway | LLM 供应商网关、BYOK 探测与能力分档预设 |
| packages/agents | Agent 编排与提示词资产 |
| packages/humanize | 内容人性化改写 |
| packages/adapters-xhs | 小红书平台适配器 |
| packages/adapters-1688 | 1688 平台适配器 |
