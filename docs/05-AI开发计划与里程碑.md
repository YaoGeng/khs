## 5. 跨阶段依赖与关键路径

```
T-PRE → M0(授权/接管/spike) → M1(采集/报告/热更) → M2(选品) → M3(发布) → M4(推广) → M5(商业化) → M6(合规)
```

- **关键路径**：授权链路（M0）→ 适配层框架与 DSL v1.1（M1 的 T-M1-01/02）→ 1688 适配（M2）→ 发布幂等（M3，依赖 DSL verify）→ 推广（M4）→ 支付（M5）。任一延误 1:1 推移总工期。
- **可并行**：服务端后台建设（M5 的 T-M5-03）可提前到 M3 起由服务端工程师滚动开发；B 端 P0 页面结构已定（§12.2），不阻塞关键路径。
- **共同设施**：适配层热更机制是 R1 的长期保险，M1 建立后 M2/M3/M4 每个适配层复用，不重复建设。

## 8. 变更与门禁机制

1. **范围变更**：任何 P0 增删、门禁标准调整须经 PM + 产品 + 架构三方会签，记录入计划 v-next；P1 调整 PM 单方可决。
2. **门禁会**：每里程碑最后一周五召开，按本计划门禁表逐项判定（只写"通过/未通过"），未通过项转返工任务卡，结论归档。
3. **任务卡流转**：周会派发，每次只派一个 READY 任务；执行方返回完成报告（产物/证据/自测/风险），无证据项一律判未通过。
4. **工期偏差**：任一里程碑偏差 > 1 周，PM 发起计划重基线（re-baseline），优先保 M6 合规审查不被压缩。
