## 0. 文档说明

本说明书在原始 10 条需求基础上做三件事：

1. **补全缺口**：原需求未覆盖的支付、通知、数据管理、风控、验收标准等；
2. **明确语义**：消除歧义（如"openapikey"明确为 BYOK 模式，"electoral 客户端"明确为 Electron 桌面客户端）；
3. **建立编号**：每条需求有唯一编号（FR-x.y / NFR-x），架构文档与测试用例按编号追溯。

### 0.1 对原始需求的两处关键解释

| 原始表述 | 本文档的解释 |
|---|---|
| "c端 electoral 客户端工具" | 理解为 **Electron 跨平台桌面客户端**（Windows / macOS，Linux 不保证） |
| "工具支持 openapikey，需额外自行购买" | 理解为 **BYOK（Bring Your Own Key）**：用户自行购买任意 OpenAI 兼容协议的 API Key，填入客户端本地加密存储；平台**不转售、不经手、不上传**用户 Key。会员费（月/季/年卡）与 LLM 调用费完全分离 |

> 宣传与文案口径统一（PC-12）：涉及 Key 与数据上传的表述统一为「不上传至星链服务器，仅直连（或随调用发往）你所配置的 LLM 服务商」，禁用「永不上传」类绝对化措辞；EULA 与官网/宣传物料同步该口径。

## 1. 产品概述

### 1.1 定位

面向小红书电商个体卖家/小团队的桌面端 AI 工作流工具：从「市场需求洞察 → 1688 智能选品与货源对接 → 笔记批量发布 → 评论区合规引流」全链路半自动化，人工在关键节点确认，AI 与浏览器自动化完成重复劳动。

### 1.2 产品形态

| 形态 | 说明 |
|---|---|
| C 端 | Electron 桌面客户端（Windows 10+ / macOS 12+），离线可查看历史数据，联网执行工作流 |
| B 端 | Web 后台管理站点（运营/客服/财务/管理员使用），管理账号、会员卡、订单、风控与数据看板 |

### 1.3 价值主张

- **市场调研提效**：关键词 → 笔记采集 → AI 需求报告，替代人工刷帖；
- **选品决策提效**：多维评分模型 + 候选清单对比 + 供应商初筛沟通；
- **内容生产提效**：商品素材 → 多风格笔记草稿 → 人工确认后定时发布；
- **引流动作可控**：帖子筛选 + 评论内容审核 + 频控熔断，把账号风险显性化。

### 1.4 商业模式

| 项目 | 说明 |
|---|---|
| 会员卡 | 月卡 / 季卡 / 年卡，按设备数分档（个人版 1 设备、团队版 3 设备），通过激活码或在线支付开通 |
| LLM 费用 | 用户自备 OpenAI 兼容 Key（BYOK），平台不经手；客户端提供用量与成本统计 |
| 增值项（二期） | 素材云盘扩容、子账号席位。（决策记录 PC-11：原列「云端代理 IP 池订阅」与 §5.2「不绕过反爬」定位直接冲突，已移除；如商业上坚持保留，须产品与法务联合决策后方可排期，未决策不排期。用户自配 HTTP/SOCKS5 代理保留，见 §5.3 网络层） |

### 1.5 成功指标（北极星）

- 核心北极星：**单用户月均「成功发布笔记数」与「选品→对接货源转化率」**；
- 护栏指标：账号风控事件率（用户上报小红书/1688 账号异常的比例）< 2%/月；P0 崩溃率 < 0.1%。

## 2. 角色与用户故事

### 2.1 角色定义

| 角色 | 端 | 描述 |
|---|---|---|
| 卖家用户（个人/团队） | C | 核心使用者，执行选品/发布/推广工作流 |
| 运营管理员 | B | 会员卡发放、激活码管理、公告、风控处置 |
| 客服 | B | 工单处理、账号解绑重置、退款协助 |
| 财务 | B | 订单对账、发票、收入报表 |
| 系统管理员 | B | 权限、配置、审计日志 |

### 2.2 核心用户故事（与 FR 编号对应）

1. 作为卖家，我用邮箱注册并登录客户端，购买月卡后立即可用（FR-1.x）；
2. 作为卖家，我填入自己购买的 DeepSeek/OpenAI Key，客户端本地加密保存并验证可用性（FR-2.x）；
3. 作为卖家，我点一个按钮，客户端用我的专用浏览器 Profile 打开小红书/1688 并自动接管，我自己扫码登录（FR-3.x）；
4. 作为卖家，我输入"露营灯"主题，工具采集相关笔记并生成需求报告（FR-4/FR-5）；
5. 作为卖家，工具按报告去 1688 找货、打分、出候选清单，我勾选后工具收藏店铺并代发询盘话术（FR-6）；
6. 作为卖家，我确认货源到位后，一键进入发布流程（FR-7）；
7. 作为卖家，我勾选商品、选"种草风"，工具生成文案、套图、排队定时发布（FR-8）；
8. 作为卖家，我设置广告话术和帖子热度阈值，工具筛选合适帖子并排队评论，全程有频控和熔断（FR-9）；
9. 作为卖家，我能回看每一次自动化操作的日志和截图（FR-10）；
10. 作为运营，我在 B 端发放季卡激活码、看到收入看板、处置被投诉的异常账号（FR-11.x）。

## 5. 安全、反爬与合规（独立章节）

> 本章是产品级红线与工程策略的集合，架构文档 §11 给出对应的技术落地。以下所有阈值均为**默认出厂值**，用户只能下调不能上调。

### 5.1 威胁模型（我们要防什么）

| 威胁 | 影响 | 主要防线 |
|---|---|---|
| 平台（小红书/1688）风控识别自动化 | 用户账号被限流/封禁 | 拟人行为模拟、频控配额、熔断、指纹降噪（§5.3） |
| 用户 LLM Key 泄露 | 用户资金损失、信任崩塌 | 系统级加密存储、脱敏展示、永不上传（§5.4） |
| 会员体系被破解/共享 | 收入损失 | 设备绑定、验签、激活码风控（§5.6） |
| 客户端被逆向/篡改 | 盗版、恶意注入 | 代码混淆、完整性校验、授权离线签名 |
| 用户发布违禁内容被处罚 | 法律与平台处罚风险 | 内容合规过滤、人工确认门禁（§5.5） |
| 我方服务器被拖库 | 用户数据泄露 | 服务端最小化存储、字段级加密、RBAC + 审计 |

### 5.2 法律与平台合规红线（产品门禁）

| 红线 | 产品化处理 |
|---|---|
| 平台用户协议限制自动化抓取与批量操作 | 软件定位为「**用户自有账号下的操作效率工具**」：不替用户注册、不养号、不绕过验证码；一切自动化在用户已登录的本人会话内以拟人速率执行；EULA 中明示风险并由用户确认自担 |
| 评论广告可能构成垃圾信息/不当导流 | 频率硬上限 + 内容相关性要求 + 待审池人工确认默认开启；禁止采集/评论涉政、医疗、金融等高危类目帖子（类目黑名单） |
| 《广告法》违禁词 | 文案生成与评论内容强制过违禁词库（见 §5.5），命中阻断并提示改写 |
| 著作权 | 素材留存仅限用户选品自用；发布流程默认使用用户已获授权的供应商素材，EULA 明确侵权责任归属用户；提供图片 MD5 去重避免重复铺图 |
| 个人信息 | 采集数据仅含公开笔记内容与公开店铺信息，不采集 C 端用户画像；本地存储，不上传 |
| 数据安全 | 星链服务器侧用户数据出境默认为否；LLM 调用内容由用户自选服务商（可能为境外服务商，配置界面有境内外标注，FR-2.7），客户端在配置与调用前提示「内容将发送至你所配置的 LLM 服务商」；发送内容默认经去标识化处理（FR-5.1） |

### 5.3 反爬与拟人策略引擎（对应原需求 4.1 的落地）

**设计原则：不是「绕过反爬」，而是「行为速率与分布拟人化 + 风控信号熔断」。**

策略引擎五层（架构文档 §7 详述）：

1. **节奏层**：请求间隔随机化（默认 3–8s 截断正态分布）、滚动深度/停留时长拟人、每日配额（采集默认 300 条/日、评论 ≤30 条/日、发布 ≤10 条/日）；
2. **行为层**：贝塞尔曲线鼠标移动、随机视口停留、非工作时段（02:00–07:00）默认禁跑；
3. **指纹层**：单一固定 Profile（与用户日常使用的指纹一致），不注入高风险指纹伪装；内置 Chromium 与自动化特征降噪（去除 webdriver 标记等基础项）；
4. **熔断层**：验证码出现、HTTP 429/401 突增、评论失败率 >20%/10 分钟 → 立即暂停任务、弹窗引导人工处理、冷却 30 分钟后可手动恢复；
5. **网络层**（可选）：支持用户自配 HTTP/SOCKS5 代理（用户自身网络环境，保留）；官方代理池已从二期规划移除（决策记录 PC-11，见 §1.4）。

**可借鉴的高 Star 开源项目（详见架构文档 §7.4）：** DrissionPage（CDP + 拟人化国产库，Star 高且中文文档友好）、playwright-stealth / rebrowser-playwright（指纹降噪思路）、puppeteer-extra-plugin-stealth、Crawlee（请求调度/重试/会话池设计）、MediaCrawler（仅作字段与交互研究参考，不自建接口逆向）。

### 5.5 内容合规过滤管线

1. **违禁词库**：广告法极限词（最/第一/国家级…）、医疗功效词、金融承诺词；本地库 + B 端下发更新；
2. **导流变体库**：谐音、符号穿插、emoji 替换等变体正则集，评论内容必过；
3. **类目黑名单**：涉政时事、医疗（含医美整形、医疗器械，对应社区规范 3.1.3）、金融投资类帖子不进入评论候选；违禁物品类目（社区规范 2.3.1：处方药物、烟草、投资理财产品等）内容不进入文案生成与评论候选；
4. **三道闸**：生成时过滤 → 待审池标红提示 → 执行前终检；命中即拦截并给改写建议。

### 5.6 会员与授权安全

- 许可证 = 服务端私钥签发的 JWT（含 user_id、套餐、到期时间、设备指纹哈希），客户端公钥验签；
- 设备指纹 = 主板/磁盘/MAC 哈希混合 + 随机盐，B 端可强制下线；
- 激活码：16 位分段码，防爆破（单 IP 10 次/小时，错误 5 次锁码），一经兑换即绑定；
- 离线宽限 72h，超时需联网验签（防克隆共享）。

### 5.7 应急响应预案（Runbook 摘要）

| 事件 | 触发 | 动作 |
|---|---|---|
| 平台改版导致流程失效 | 选择器自检失败率告警 | B 端远程关闭对应工作流入口（Feature Flag）→ 热更新选择器 → 灰度恢复 |
| 大面积账号风控反馈 | 客服工单聚类告警 | 全量下调默认配额（远程配置）→ 公告提示 → 复盘策略 |
| 授权服务宕机 | 监控告警 | 客户端自动进入 72h 宽限模式；B 端挂维护页 |
| Key 泄露投诉 | 工单 | 指引用户吊销重配；核查客户端日志确认非我方泄露（Key 不出端可自证） |

## 6. 验收标准与埋点指标

### 6.1 关键链路验收（摘选）

| 链路 | 验收标准 |
|---|---|
| 注册→开卡→登录 | 支付回调→会员生效→可签发许可证链路 P95 ≤ 30s（C-4）；激活设备数超限被阻断并提示解绑 |
| 一键打开受控浏览器 | 点击后 ≤5s 浏览器拉起并完成 CDP 接管；重启客户端登录态保持 |
| 采集→报告 | 100 条笔记采集完成率 ≥95%（剔除平台限制）；报告八章节齐全且引用数据来源；请求间隔不低于配置下限、日配额触顶自动停止并可跨日续采 |
| 选品→询盘 | 评分模型输出可解释（每个维度有分值与理由）；询盘话术发送前有人工确认记录 |
| 发布 | 队列 10 条笔记按间隔执行，重复发布为 0；失败任务有截图与原因 |
| 推广 | 频控硬上限不可被配置突破；熔断触发后任务自动暂停且有通知 |
| 验证码熔断 | 模拟注入验证码组件 → 任务自动挂起、无自动重试、不自动切换代理、界面引导人工处理、冷却后经人工确认恢复 |
| 会话有效性 | 无有效登录态时自动化步骤不执行（挂起并引导重新登录） |
| 内容合规 | 注入极限词/变体词/黑名单类目样例，三道闸均拦截且不可绕过；词库热更后即时生效；AI 生成标识与「素材已获授权」勾选生效 |
| EULA 与遥测 | 未确认 EULA 无法进入主功能，确认记录含版本号与时间戳；未同意遥测时漏斗/埋点/熔断事件均不上传 |
| 日志 | 任选一条已执行工作流，可从日志面板完整回放时间线 |

### 6.2 埋点指标（B 端看板）

- 漏斗：注册 → 激活 → 配置 Key → 首次采集 → 首份报告 → 首次选品 → 首次发布 → 首次推广；
- 留存：次周/次月留存；会员续费率；各套餐占比；
- 质量：工作流成功率、熔断率、崩溃率、LLM 平均成本/任务。

## 7. 边界与明确不做

1. **不做**账号注册/养号/解封服务；**不做**验证码破解（触发即转人工）；
2. **不存储**用户平台账号密码，**不承诺**「永不封号」；
3. **不转售** LLM Key，不做云端代跑（V1 全部本地执行）；
4. **不做**小红书私信群发（风控与合规风险过高，V1 仅评论）；
5. **不做**接口逆向抓包采集（仅页面级 CDP 采集，速率拟人）；**不修改平台客户端、不向平台页面注入脚本**（区别于社区规范 2.3.1 所列「外挂程序」：浏览器为应用托管的独立进程——内置便携 Chromium 或本机 Chrome/Edge，登录由你本人在可见窗口完成，应用不读取、不存储平台账号密码）；
6. 1688 下单/支付不自动化，采购环节完全由用户人工完成。
